## Scope

The repository is a scaffold: module stubs with no logic, a CLI that
reports "not implemented", and a skill whose body refuses to run. The
tests therefore check the few properties the scaffold must already
guarantee, not behaviour.

## Tests

### `test_package_version_is_semver`

- **What**: imports `agent_brainswarm` and matches `__version__` against
  `\d+\.\d+\.\d+`.
- **Why**: confirms the package is importable from `src/` under the
  configured `pythonpath`, and that the version string is well-formed for
  packaging.
- **Input rationale**: the regular expression is the minimal semantic
  version shape (major.minor.patch); pre-release suffixes are not used by
  this project.

### `test_cli_reports_not_implemented`

- **What**: calls `cli.main(["validate"])` and asserts exit code 1.
- **Why**: the scaffold CLI must fail loudly rather than appear to succeed
  while doing nothing.
- **Input rationale**: `validate` is the first subcommand that will be
  implemented; any listed subcommand exercises the same code path.

### `test_skill_is_named_brainswarm`

- **What**: parses the frontmatter of `.claude/skills/brainswarm/SKILL.md`
  and checks for `name: brainswarm` and an explicit mention of
  "brainstorm".
- **Why**: the skill name is the invocation contract (`/brainswarm`,
  "brainswarm …"), and the description must explicitly exclude
  "brainstorm" so the expensive pipeline is never triggered by casual
  phrasing (`docs/DESIGN.md` §3).
- **Input rationale**: the repository's own skill file is the only relevant
  input.

## Failures and fixes

`ty check` initially reported one diagnostic on the first version of the
version test, `assert agent_brainswarm.__version__`: the inferred type
`Literal["0.0.1"]` is always truthy, so the assertion could never fail and
tested nothing. It was replaced by the semantic-version match above, which
can fail. No test failed at runtime.
